# Independent Approval Layers

| Layer | Establishes | Does not establish |
| --- | --- | --- |
| Task authorization | Requested/permitted action, target, phase, decisions, and exclusions. | Runtime access or persistence of a prior grant. |
| Harness permission | Runtime access to a tool/resource/effect within actual conditions. | Content acceptance, publication authority, another target, or a later phase. |

| Task action authorized? | Current access valid? | Next step |
| --- | --- | --- |
| Yes | Yes | Execute and verify within scope; no attendance ritual. |
| Yes | No/unknown | Establish access under current tool rules; request required runtime permission without repeating the task decision. Arrange attention only for a concrete expected interaction. |
| No/unresolved | Yes | Preserve the decision gate for this action; continue independent authorized work. |
| No/unresolved | No/unknown | Prepare within existing authority, then resolve each prerequisite separately. |

If action A is authorized but later B is pending, describe A accurately. If one call also performs B, split it or obtain B's authority. A runtime grant cannot resolve B's task decision.

## Forecast effects and schedule attention

Use documented effects, known grants, and observed prompt behavior to forecast interaction. Reversibility does not establish permission-free execution; different tools or surfaces can have independent access controls. An unknown boundary is an uncertainty to manage under actual tool rules, not an automatic human-wait condition. Never broaden access or simulate approval UI to test or shorten the process.

An attended block groups ready operations and human attention; it need not be one call or one grant. Have inputs, required decisions, bounded effects, and essential checks ready. Finish the block promptly or close it safely when readiness is lost. Authorized work with valid access continues without attendance. Track waiting, execution, dialog count, and attended periods only to the extent observable; do not claim that this method guarantees fewer prompts.
