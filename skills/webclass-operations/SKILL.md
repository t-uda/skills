# WebClass Operations

Own the applicable platform schema, mapping to controls/imports, and verification of actual delivery. Read [the attribute model](references/material-model.md) for discovery and planning. In Codex, also read [the browser adapter](references/codex-browser.md); it is conditional guidance, not a validated cross-agent integration.

Resolve named companions from available skills or their source; sibling links locate them in this repository, not in every single-skill installation. If unavailable, report the capability gap and continue independent work; do not install or activate them implicitly.

## 1. Discover requirements before finalizing content

Identify the actual course, object types, identities, owners, operational state, and preservation constraints. Inspect the current UI, including conditional controls for relevant material/question types. Establish attribute scope, meaning, dependencies, allowed values, and import/UI routes. A CSV header is not a platform schema. Feed applicable requirements to [teaching-materials](../teaching-materials/SKILL.md) before finalizing a creation or migration design.

For a bounded edit, reuse validated schema/state and inspect affected fields and dependencies; expand discovery when object type or UI changes. A small image/text edit does not require whole-course inventory or a scoring audit.

## 2. Resolve the shared target model

Combine schema and observed state with the applicable content/evaluation version in the task's existing source/model. Follow [the model contract](references/material-model.md), including identity/version, observed versus intended values, provenance, preservation, unresolved/not-applicable state, transfer route, and verification. This workflow updates platform definitions, observations, mappings, and application/check status; the content workflow updates semantic requirements and acceptance status.

Resolve consequential unknowns before writing the affected target; continue independent authorized investigation and preparation. Defaults, absent import columns, and uninspected controls are not decisions. If accepted semantics cannot be represented, return the concrete mismatch and feasible alternatives to the content workflow. Reconfirm only the affected choice under its existing decision authority, update the same version/model, and regenerate affected mappings before execution. Do not silently approximate or reopen unrelated accepted content.

## 3. Plan intermediate states, then apply

Derive imports and remaining UI edits from that same model. Confirm control meaning/polarity and serialization. Inspect whether import, copy, and each save make incomplete content visible, attemptable, or graded. If an actual draft/private staging mode exists, verify its behavior and use it within task authority until required settings and checks are complete. Do not assume a transaction or invisible import.

Without staging, determine the effect of each intermediate state and choose a safe dependency order. If incomplete exposure cannot be avoided within existing authority, pause the affected write and resolve only the necessary exposure/timing/delivery choice; continue preparation. A content version's acceptance does not independently authorize release. Preserve protected started materials and historical results; staging must stay within authorized access and grading scope.

Execute only authorized actions. Load [human-intervention-management](../human-intervention-management/SKILL.md) for actual/expected permission, authentication, reserved-decision, or recovery needs; supply immediate effects and save/submit boundaries. Valid access and authority permit autonomous continuation. Refresh/reconcile the relevant baseline before overwrite when external edits may have occurred. Finish required save stages; inspect state before repeating an uncertain write.

## 4. Reopen, interpret, and compare

Reopen changed and relevant preserved attributes and compare interpreted saved values against the target model. Inspect actual rendering of affected content. Where relevant and safe within authority, check accepted/rejected behavior without altering student attempts or results; otherwise mark behavior untested. An import success, saved notice, screenshot, or captured value is evidence to interpret, not verification by itself.

Record discrepancies and check status in the same model. Repair within authority and recheck affected dependencies. Complete authorized release only after required settings and available checks pass; report any checks that cannot safely precede release and resolve a necessary reserved decision before proceeding.

## 5. Report the verified scope

Distinguish preparation, applied changes, independently read-back state, rendered/behavioral checks, and user-reported changes. Report unknowns, unsafe intermediate states, and delivery limits. Content correctness remains with teaching-materials; external-drive/Box synchronization belongs to its separate workflow. Course identities, dates, exact-match rules, points, and ownership mappings are task data, not reusable defaults.
